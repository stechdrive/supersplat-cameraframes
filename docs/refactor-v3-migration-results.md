本家v3.1.2 / Engine 2.22.1を使用。通常エントリのbuild、lint、typecheck、Nodeのカメラ状態7件と既存投影との比較4件が成功した。依存パッケージのSass legacy API・mediabunny循環参照等のビルド警告は残る。

検証用エントリ `tests/browser/index.ts` を `npm run build:validation` で生成し、ローカルChromeの実WebGPUで実行した。通常ビルドには試験ボタンを含めない。配信は `npm run serve:validation`、通常入口への復帰は `npm run build`。

- 合成2 Splatを同じresource/instancesから2ビューへ描画。view単位に投影・sort資源を所有する。
- 撮影カメラのX移動前後で、左ビューのRGBA差は最大0・平均0。右ビューは最大193・平均1.892734で変化し、位置を戻すと復元する。
- 左右それぞれでpick、中心選択、footprint選択、深度選択が成功。
- ビューポートのorbitと撮影previewの倍率・panで、撮影文書と出力viewは変わらない。
- WebGPU validation errorは0。ターゲットは左722×1794、右723×1794。
- 実機UIで右ビューの移動gizmoを操作してSplatのXが0→0.353、Undoで0へ復元。左ビューの移動gizmoでYが0→0.232。両画面へ反映した。

この段階は描画基盤の確認。製品統合の結果は以下へ追記する。小さな合成素材の結果から大規模シーンの性能を推定しない。

上流との差分は `docs/refactor-v3-migration-plan.md` を参照。Engineパッケージのソースは変更していない。ESLintはimportプラグインのpeer互換性のため9.39.4を維持し、TypeScriptは6.0.3、CIのNodeは24へ更新した。

## 製品の保存・出力と旧プロジェクト（2026-09-13）

既存の撮影カメラ、フレーム、下絵、GLB・照明のUIを新しい状態と描画へ接続した。静止画の出力は専用カメラ・描画ターゲットを所有し、通常の二つのビューは変更しない。

Chrome実機で次を確認した。合成素材のレポートは検証ページから `.v3-proof/migration-results/report.json` へ保存する。実素材・生成物はignore対象でありコミットしない。

- GLBの前後のSplatを、左右両方のペインで選択。標準mesh深度を使う。
- 四色の下絵を撮影ビューへ表示し、方向・RGB・alphaを画素で照合。ビューポート画像は差0。
- PNGとPSDを実際の製品関数から生成し、PSDを再デコード。未遮蔽GLB画像と、Gaussianの透過率を持つ独立レイヤーマスクを確認。
- Splat別の元画像と独立マスク、グリッド／アイレベルのPSDレイヤーを確認。複数の不透明GLBの前後関係もマスクへ反映した。
- 四隅の各anchorへ1.5倍拡張し、元の320×240領域を切り出して基準画像と比較。最大RGBA差1以下。
- Splat、instanceの選択、撮影カメラ、GLB、下絵を本家v1の資源・instance構造で保存し再読込。保存前後の出力画像の最大RGBA差1以下。
- Ctrl+S相当の作業保存、同一パッケージからの作業状態復元、`*`と`PKG`の分離を確認。既存資源はパッケージ内のファイルを参照し、編集instanceと追加資源をIndexedDBへ保存する。
- 撮影カメラのgizmo経路を動かし、指定したカメラだけが変わること、別の撮影カメラとビューポートは変わらないこと、Undoと複数カメラの`.sscam`再読込を確認。
- 実機UIで撮影カメラのX位置を0→0.4、rollを0→45へ変更し、Undoを2回行って0へ戻ることを確認。
- 通常入口でも分割表示・カメラ複製・フレーム追加を操作。複製側のBフレームを120%へ変更しても、元カメラはAフレーム100%のまま保持した。
- 通常UIでビューポートのレンズを50mmへ変更し、撮影カメラの31.2mm表示が変わらないことを確認。
- ブラウザの実FileSystemFileHandle（検証専用OPFS）へ上書き保存。削除したSplatのUndo、再保存、再読込後も出力画像の最大RGBA差1以下。履歴が所有する遅延読込資源も上書き前に保護する。
- 上記合成試験終了までWebGPU validation errorは0。

ローカル旧プロジェクトは4,633,167 Gaussianを含み、旧形式の圧縮ZIPから約5.5秒で読み込めた。保存済みFPV位置は誤差1e-8未満、1754×1736のPNGを出力し、バイクと撮影フレームを目視確認した。この値は当該素材での一回の測定であり、従来版との性能比較ではない。

同素材を約1083MiBの新パッケージへ保存し、再読込した。全Gaussianの位置・形状・色を65536行ずつSHA-256で照合し、全Float32ビットが一致した。撮影カメラ文書も一致する。最終試験では同一データの連続描画でRGBA最大差143・平均0.2032、保存再読込後は最大148・平均0.2602を観測した。大素材は画素の完全一致を保証せず、元データの完全一致と、連続描画と同程度の画素差を確認する。小素材の最大差1以下とは区別する。

Nodeテストは19件成功。撮影データの独立性・履歴・Quaternionのpole/roll、旧orbitのframing lock、保存形式の不正値・切断データの拒否、PNGのstraight RGBAと150dpi情報、PSDマスクの部分遮蔽を含む。旧投影との照合は別途4件成功。

旧圧縮ZIPのPLYは本家のランダムアクセス読込へ直接渡せないため、そのentryだけを4MiB単位でBlobへ展開する。新パッケージは本家のPLY資源＋instance形式を使用する。圧縮SOGやDEFLATEで小さくなっていた旧パッケージより保存ファイルが大きくなる場合がある。ZIP32上限は書込前に保守的に検査し、既存ファイルを途中まで書き換えない。

## 置き換えた境界

| 旧実装 | 移行後 |
| --- | --- |
| `camera-frames.ts` とカメラの退避・復元 | `cameras/camera-store.ts`、`camera-editor.ts`、`camera-history.ts`。既存UIのイベントを文書の変更へ接続 |
| 独自projection callback | `render-view.ts` → `apply-view.ts`。Engineの標準`projectionOffset` |
| merged/unifiedとEngine shader chunk差し替え | 本家`editor-splat-resource.ts`、`gaussian-instances.ts`、`projected-splat-renderer.ts`。同時表示viewだけが投影資源を所有 |
| 表示カメラを一時的に出力へ転用 | `shot-renderer.ts`の専用カメラ・レイヤー・描画ターゲット。完了／失敗時に解放 |
| GLB／Splatの表示状態を変更してPSDを生成 | 出力専用レイヤーの所属だけを切替。GLBの前面alphaは標準depthを保持する追加passで取得 |
| 独自の圧縮資源／snapshot保存 | 本家v1資源＋instanceと、`doc-camera-frames.ts`／`doc-working.ts`の製品メタデータ |

撮影・フレーム・下絵・モデル管理の既存UIは継続する。編集ツールと外観の設定は、移行先の本家UIへ接続している。Spark版リポジトリは変更しない。

旧メンテナンス案内は起動時に自動表示しない。更新通知は作業状態／パッケージの未保存状態を確認してから再読込する。

## 適用範囲と未確認事項

- PSDの保証対象は不透明な単純GLBの元画像／Gaussian遮蔽マスク。半透明・屈折・複雑な材質を含むGLBは実素材で未確認。
- Splat別レイヤーは従来と同じ色・alphaからのマスク復元を使う。異なる色のGaussianが複雑に入り交じる結果を、一枚のPSDマスクで厳密に再現できるとは限らない。
- 大規模Splatは同じ状態の再描画でも上記の局所的な画素差がある。投影・sortは本家の実装を使用し、決定的な順序を与える独自shader改変は加えていない。
- タイムラインのカメラ経路は独立したビューポートを対象とする。永続的な撮影カメラのアニメーション機能は今回追加していない。
- 撮影カメラのRMB＋WASD連続操作、特殊な下絵overrideの全組合せ、配布済みPWAのインストール状態からの更新、他GPU／他ブラウザは未確認。公開・リリース作業は行わない。
- 小素材の実FileSystemFileHandle試験と、大素材のローカルファイルへの書込試験は別に扱う。大素材のOPFS書込はブラウザストレージの容量制限で拒否され、元パッケージを変更せずに終了した。
