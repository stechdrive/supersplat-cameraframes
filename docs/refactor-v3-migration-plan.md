## カメラとビューの契約

撮影データの正はカメラ文書だけとする。Engine Entity、Euler表示、投影行列、preview gateは導出値。orbitの正規化距離や一時退避した別の姿勢を撮影カメラの保存元にしない。複製時はIDと可変データを独立させ、削除時には参照を同時に修復する。

viewはカメラID、ペインID、scene/view revision、確定した姿勢・投影・解像度を持つ。描画、pick、gizmo、参照画像、出力で同じsnapshotを使う。編集ビューの観察と撮影カメラの編集を別操作にし、左右どちらを操作しても出力対象は明示したカメラIDで固定する。

描画資源の所有権は本家のresource/instancesを使用する。カメラ数だけSplatを複製しない。同時表示するviewの投影・sort資源の寿命を実機で検証し、共有できない一時資源はview単位で持つ。

## 維持する製品契約

- 既存UIの全面刷新とSpark版の変更は行わない。追加する操作は複数撮影カメラと分割表示に必要な範囲とする。
- `docs/save-model.md` のCtrl+Sによる作業保存、パッケージ保存、`*` / `PKG`表示、終了確認を維持する。
- 旧 `.ssproj` のversion 0/schemaVersion 4までと、本家version 1は別の構造として読み分ける。カメラと参照画像の意味を数値versionだけで判定しない。
- PNGの解像度情報、PSDの未遮蔽元画像と独立マスク、参照画像の前面/背面・レイヤー構造を維持する。
- 個人素材、生成物、ローカルAGENTS.mdはignoreのまま。共有テストには合成データを使う。

## 証拠の記録

従来のv3.0.0実証結果は変更せず、3.1.2で再検証した結果を別に記録する。自動テスト、GPU画素比較、実機UI操作、未実施を分ける。小素材のGPU時間から大規模シーンの性能を断定しない。リリース公開・pushは今回のコミット完了とは別とする。
